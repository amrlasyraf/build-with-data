Three roles, one model

The value of an all-in-one project is continuity. Each role can see where its input came from, what assumptions were made, and who uses the result next.

Role Responsibility in this project Status
Data Engineer

Validate files, load Bronze, transform Silver, aggregate Gold, and prove the output is trustworthy.

 Implemented
Data Analyst

Turn Gold metrics into a Power BI report that explains sales, category mix, channel performance, and estimated gross profit.

 Report available
Data Scientist

Build a time-aware forecast, compare it with a naive baseline, and document when the prediction should not be trusted.

 Proposed

Questions before tools

Power BI and machine learning are useful only when they answer a defined question. These two questions keep the project focused.

Current analytics question
How do sales and estimated gross profit change by month, product category, and sales channel?
Proposed forecasting question
Given history up to this month, what gross sales might each category and channel produce next month?

Run it locally

Start with the working pipeline

  1. Download and extract the repository.
  2. Double-click START_HERE.bat.
  3. Wait for Bronze, Silver, and Gold to finish.
  4. Double-click OPEN_DATA.bat to query the result.
git clone https://github.com/amrlasyraf/build-with-data.git
cd build-with-data
python -m venv _local\.venv
_local\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python run_pipeline.py
python -m step_06_optional.power_bi.export_gold

Project roadmap

The core stays runnable at every phase. New layers are added only after the previous output has a clear contract and validation.

Phase 1 · Complete

Reliable data foundation

  • Local Medallion pipeline
  • Independent stage retries
  • Automated tests and DQ history
  • DuckDB data explorer
Phase 2 · In progress

Business analysis

  • Gold CSV export ready
  • Power BI report file available
  • Reconnect the CSV source on your computer
  • Documented findings
Phase 3 · Proposed

Forecasting experiment

  • Chronological train/test split
  • Naive seasonal baseline
  • One interpretable model
  • MAE plus limitations
No pretend prediction: the model phase is successful only if it beats a clearly defined baseline on unseen months. If it does not, that result will be reported honestly.
